# ハイライトカバー 案出し（第2案）

`cover_proposals.png` が比較シート。実際のハイライト表示サイズ（円形）で並べてある。

## 経緯

第1案（生成り地に墨の明朝で漢字2文字）は**却下**。
理由は明快で、**投稿と合っていない**。

- フィードは明るい・清潔・ナチュラルな料理写真
- 第1案は墨×明朝の高級店の語彙で、別のアカウントに見える
- カバーだけ浮いて、プロフィール全体の統一感が壊れる

第2案では方針を変え、**カバーをフィードと同じ素材（＝投稿写真）で作る**ことを前提にした。

## 4案

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A** | 投稿写真をそのまま（文字なし） | フィードと完全に地続き。最も自然 | 中身が推測しづらい（ラベルは下に出る） |
| **B** | 写真＋白ベール＋中央に文字 | 統一感が出る。料理アカウントで最多の型 | **料理が白く飛んで、写真の強みが消える** |
| **C** | 写真＋下に白い帯 | 写真が大きく残り、文字も確実に読める。明るさのバラつきに強い | やや情報量が多い |
| **D** | 淡い単色＋絵文字 | 最も手軽。増やすのが一瞬 | 清潔なフィードに対して絵文字が軽く見える |

## 推奨

**C → A の順。**

このアカウントは**料理写真そのものが最大の資産**なので、
Bのように白で飛ばすのは持ち味を消してしまう。
Cなら写真を大きく見せたまま、何のハイライトかも分かる。

## 本番で作るときの注意

比較シートの写真は**プロフィールのスクリーンショットから切り出した低解像度**のもの。
採用する案が決まったら、各ハイライトの中身から元データで選び直して作る。

- 写真は**そのハイライトの中身から選ぶ**（出張料理の枠には出張の写真）
- カバーは**中央の正方形**が円形に切り抜かれる。料理を必ず中央に
- 4枚のトーン（明るさ・彩度）を揃える。バラつくと並びが散らかる

---

## 第2案の結論：写真は「そのハイライトの中身」から選ぶ

依頼者の判断。**カバーを見ただけで中身が分かる**のが最優先。
→ 写真ベースの案A（写真だけ）か案C（写真＋白帯）に絞られた。

### 制作テンプレート

`cover-builder.html` がそのまま書き出しに使える。

1. 写真4枚を `feed/` に `p0.jpg`〜`p3.jpg` として置く（正方形に近い形で用意）
2. ブラウザで開く
3. 各セクションを 1080×1920 でスクリーンショット

`sample/` に現時点の出力例が入っている（写真は仮）。

### 重要な仕様

**Instagramは画像の中央の正方形を円形に切り抜く。**
テンプレートは写真を **y=420〜1500 の中央1080×1080** に配置しており、
この範囲がそのまま円になる。**写真の主役は必ずこの中に置く。**

案Cの白帯は `top:1284px` に固定してある。これは円の内側に確実に収まる位置。
ここより下げると帯が円から外れて消える。

### 写真の選び方

案Aは文字がないぶん、**4枚の被写体が似ていると区別がつかない**。
料理写真ばかりを並べず、被写体をずらす。

| ハイライト | 選ぶべき被写体 |
|---|---|
| はじめまして | コック服（人）。料理でないことで並びの起点になる |
| 間借り出店 | 店先・看板・営業中の風景。料理そのものより「場所」 |
| 出張料理 | 大皿、配膳した卓、複数皿が並んだ引きの絵 |
| 作り置き | 保存容器、並んだ常備菜。「ストック感」が出るもの |

被写体をずらせるなら**案A**で足りる。
似た料理写真しか用意できないなら**案C**（白帯）にする。

### 4枚のトーンを揃える

明るさ・彩度がバラつくと、円が並んだときに散らかって見える。
テンプレートでは `filter:saturate(.92) brightness(1.04)` を全枚に共通でかけている。
元写真の明るさが大きく違う場合は、撮影時かテンプレート側で個別に調整する。
