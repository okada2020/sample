# ハイライトカバー 案出し（第2案）

`cover_proposals.png` が比較シート。実際のハイライト表示サイズ（円形）で並べてある。

## 経緯

第1案（生成り地に墨の明朝で漢字2文字）は**却下**。
理由は明快で、**投稿と合っていない**。

- フィードは明るい・清潔・ナチュラルな料理写真
- 第1案は墨×明朝の高級店の語彙で、別のアカウントに見える
- カバーだけ浮いて、プロフィール全体の統一感が壊れる

第2案では方針を変え、**カバーをフィードと同じ素材（＝投稿写真）で作る**ことを前提にした。

## 4案

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A** | 投稿写真をそのまま（文字なし） | フィードと完全に地続き。最も自然 | 中身が推測しづらい（ラベルは下に出る） |
| **B** | 写真＋白ベール＋中央に文字 | 統一感が出る。料理アカウントで最多の型 | **料理が白く飛んで、写真の強みが消える** |
| **C** | 写真＋下に白い帯 | 写真が大きく残り、文字も確実に読める。明るさのバラつきに強い | やや情報量が多い |
| **D** | 淡い単色＋絵文字 | 最も手軽。増やすのが一瞬 | 清潔なフィードに対して絵文字が軽く見える |

## 推奨

**C → A の順。**

このアカウントは**料理写真そのものが最大の資産**なので、
Bのように白で飛ばすのは持ち味を消してしまう。
Cなら写真を大きく見せたまま、何のハイライトかも分かる。

## 本番で作るときの注意

比較シートの写真は**プロフィールのスクリーンショットから切り出した低解像度**のもの。
採用する案が決まったら、各ハイライトの中身から元データで選び直して作る。

- 写真は**そのハイライトの中身から選ぶ**（出張料理の枠には出張の写真）
- カバーは**中央の正方形**が円形に切り抜かれる。料理を必ず中央に
- 4枚のトーン（明るさ・彩度）を揃える。バラつくと並びが散らかる
