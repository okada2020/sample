# 連載企画「やってみた検証」設計書

## 企画

**AIキャラクターのアフィリエイトブログは、本当に稼げるのか。**
0円・フォロワー0から3ヶ月やってみる。

## なぜこの企画が効くか

| 理由 | 中身 |
|---|---|
| 構造的に嘘がつけない | 進行中の出来事を報告するだけ。捏造の余地がない |
| AIの弱点が消える | 実機レビューはできないが、**検証は実際に起きている体験**なので堂々と書ける |
| 連載になる | 「続きが気になる」構造。フォロワー0からの立ち上げに効く |
| 3本柱と地続き | ①アプリ開発 ③AI改善実績 とそのまま繋がる |
| 競合がいない | 「AIで稼げる」情報は溢れているが、**実際に数字を出す人はほぼいない** |

## ルール(これを破ったら企画が死ぬ)

1. **結論を先に決めない。** ダメだったらダメと書く
2. **数字はそのまま出す。** 都合の悪い数字ほど出す
3. **収益は1円単位で公開する。** 0円なら0円と書く
4. **やめたくなったら、やめたくなったと書く**
5. 「稼げました!」で終わらせない。**再現性の話まで書く**

> ルール1が守れないなら、検証する意味がない。

## 検証条件(先に宣言する)

| 項目 | 内容 |
|---|---|
| 期間 | 2026-09-09 〜 2026-12-08(3ヶ月) |
| 開始時点 | フォロワー0 / ブログ記事11本 / 収益0円 |
| 目標 | **3ヶ月で月1万円** |
| 使うもの | ブログ・X・Instagram・Threads・楽天ROOM・A8.net |
| 作業時間 | 1日15分(これも検証対象) |
| 報告 | 週1回。数字は全公開 |

## 毎週公開する数字

```
・フォロワー数(X / Instagram / Threads)
・ブログのPV
・記事数
・収益額(円)
・その週にやったこと
・その週にわかったこと
```

## 記事の型(毎週同じ形)

```
# 【検証◯週目】AIブログは稼げるのか|今週の数字

## 今週の結果
(数字の表)

## 今週やったこと
(3〜5個の箇条書き)

## わかったこと
(1〜2個。うまくいかなかったことを優先)

## 来週やること
(1〜3個)
```

**同じ形を毎週繰り返す**のが重要。読者が「数字だけ見に来る」状態を作る。

## 各チャネルでの扱い

| チャネル | 扱い |
|---|---|
| ブログ | 本体。週1で詳細レポート。カテゴリ「検証」 |
| X | 週1で数字だけ抜粋。**画像なしのテキストで数字を並べる**のがいちばん止まる |
| Threads | 途中経過のぼやき。「今週これがダメだった」系 |
| Instagram | 月1で数字のカルーセル(グラフ的に見せる) |

## 週次レポートの作り方

`src/weekly_report.py` が `data/metrics.csv` から数字を拾って記事の下書きを作る。

```bash
python -m src.weekly_report          # 今週分の下書きを生成
python -m src.weekly_report --week 3 # 週番号を指定
```

生成された下書きの「やったこと」「わかったこと」を埋めれば記事になる。

## 想定される落とし穴

- **数字が伸びないと書きたくなくなる** → だから型を固定して、機械的に出せるようにする
- **途中で企画を忘れる** → 週次レポートの生成をルーティンに組み込む
- **良い数字だけ出したくなる** → ルール1に戻る。悪い数字のほうが読まれる

## 終わったあと

3ヶ月後、結果がどうであれ**総括記事**を書く。

- 目標に届いたか / 届かなかったか
- 何が効いて、何が効かなかったか
- **同じことをやりたい人に再現性はあるか**
- 続けるか、やめるか

ここまで書いて、はじめて検証として完結する。
