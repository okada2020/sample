# VOD比較アフィリエイトサイト

動画配信サービス（VOD）比較・ランキング型のアフィリエイトサイトです。
掲載内容はすべて `data/` 配下のファイルから生成されるため、**案件を差し替えるだけで
ランキング・比較表・シミュレーター・診断・詳細ページが一括で更新されます。**

---

## 1. 公開までの手順

| # | やること | 触るファイル |
|---|---|---|
| 1 | ASPで提携し、発行された広告リンクを `url` に貼る | `data/services.js` |
| 2 | 料金・作品数・ポイント還元を公式サイトで確認して修正 | `data/services.js` |
| 3 | サイト名・公開ドメイン・運営者情報を書き換える | `data/site.js` |
| 4 | GA4測定ID（`G-XXXXXXX`）を入れる | `data/site.js` |
| 5 | `demoMode: false` にして警告バーを消す | `data/site.js` |
| 6 | **`node build.js` を実行し、`dist/` の中身を公開する** | — |

`node build.js` は未設定の項目を検出して警告します。**警告がゼロになってから公開してください。**

```
✓ dist/ に 18 ページを生成しました
⚠ demoMode が true です。サンプル警告バーが表示されたままになります。
⚠ baseUrl が example.com のままです。
⚠ アフィリンク未設定：U-NEXT, ...
```

## 2. なぜビルドするのか（重要）

`affiliate/` をそのまま開いても動きますが、その場合**本文をブラウザのJavaScriptが組み立てて**います。
アフィリエイトサイトは検索流入がすべてなので、これは次のリスクを抱えます。

- 検索エンジンへの反映が遅れる（JSの実行を待つ必要があるため）
- JavaScriptが1つでもエラーになると、ページが真っ白になる
- 描画待ちのぶん表示が遅く、画面がガタつく

`node build.js` はデータをHTMLに焼き込んで `dist/` に出力します。
**JavaScriptが動かない状態でも全文が読める**ため、上の3つが同時に解消されます。
あわせてURLが `service.html?id=u-next` → `service/u-next.html` に変わり、SEO上も有利になります。

> `data/` を編集したら `node build.js` を再実行してください。忘れると `dist/` が古いままになります。
> Node.js以外の依存はありません（`npm install` 不要）。

## 3. ディレクトリ構成

```
affiliate/
├─ build.js          ★ dist/ を生成する（依存パッケージなし）
├─ index.html        トップ（診断＋シミュレーター＋ランキング＋比較表＋FAQ）
├─ compare.html      全社比較表（ジャンル絞り込み）
├─ service.html      サービス詳細のひな形
├─ articles.html     記事一覧
├─ article.html      記事詳細のひな形
├─ about.html        運営者情報
├─ privacy.html      プライバシーポリシー・免責事項
├─ data/
│   ├─ site.js       サイト設定（名称・計測・追従CTA・警告バー）
│   ├─ services.js   ★掲載案件。ここが差し替えの中心
│   └─ content.js    診断・FAQ・記事本文
├─ css/style.css     共通スタイル
├─ js/
│   ├─ render.js     ★HTMLを組み立てる本体（表示の修正はここ）
│   └─ app.js        ブラウザ側の操作（診断・絞り込み・追従CTA）
└─ dist/             ← build.js の出力。公開するのはこのフォルダ
```

`render.js` はブラウザとNodeの両方で動きます。**表示を直すときは render.js の1か所だけ**を
直せば、開発表示と公開用HTMLの両方に反映されます。

**サービスを1社追加したい** → `data/services.js` に1件足して `node build.js`。
ランキング・比較表・シミュレーター・診断・詳細ページ・サイトマップすべてに反映されます。

## 4. 売るために組み込んである仕掛け

| 仕掛け | 場所 | 狙い |
|---|---|---|
| 3問の診断チャート | トップ最上部 | 選ぶ判断を代行し、迷いによる離脱を止める。結果には**選んだ条件を根拠として提示** |
| 料金シミュレーター | トップ／比較 | 「自分の場合いくらか」を数字で示す。**月額の安さと実質負担の順位は一致しない**ことを可視化 |
| 追従CTAバー | スマホ全ページ | どこまで読んでも1タップで申込へ（300pxスクロールで出現） |
| ランキングカード | トップ／比較 | 1位を金枠で強調し、視線を最も売りたい案件へ集める |
| 比較表 | トップ／比較 | 「他と比べたい」欲求をサイト内で完結させ、離脱を防ぐ |
| 記事内CTAボックス | 記事本文中 | 読了を待たず、納得したその場で渡す |
| 比較記事（○○ vs ○○） | 記事 | 申込直前の検索意図を拾う。最も成約に近い流入 |
| デメリットの明記 | 各カード | 短所を書くほうが信頼され、結果的に成約率が上がる |

### CTAの色を変えるときの注意
`css/style.css` の `--cta` は、ページ内で**最も明度・彩度が高い色**である必要があります。
基調色に馴染ませると押されなくなるため、浮くくらいで正解です。

## 5. 計測（GA4）

`data/site.js` に測定IDを入れると、タグが自動で読み込まれ、次のイベントが送信されます。

| イベント | 送信される値 | 何が分かるか |
|---|---|---|
| `affiliate_click` | `service_id` / `service_name` / `position` / `page_path` | どの案件が、どの配置で、どのページから押されたか |
| `quiz_complete` | `answers` / `result_service` | どんな条件の人が来て、診断が何を薦めたか |
| `simulator_change` | `people` | 何人で使う人が多いか（＝訴求すべき軸） |
| `compare_filter` | `genre` / `shown` | どのジャンル目的の訪問者が多いか |

`position` は `ranking_1` `table` `sticky` `quiz_result` `simulator` `in_article` の6種類です。
**どの配置が稼いでいるかを比較し、効かない配置を削る**のがCVR改善の最短ルートです。

### GA4側で必ずやる設定（ここを省くとレポートに出ません）

1. **カスタムディメンションの登録**
   「管理 → カスタム定義 → カスタムディメンションを作成」で、
   `service_name` `position` `result_service` `genre` をイベントスコープで登録します。
   **登録しないと、送信はされていてもレポートで絞り込めません。**
2. **キーイベントに設定**
   「管理 → キーイベント」で `affiliate_click` をオンにします。
   これでランディングページ別・流入元別のクリック率が見られるようになります。
3. **Search Consoleの連携**
   GA4には検索キーワードが出ません。どの語で流入しているかは
   Search Console側でしか分からないため、必ず連携してください。

### 計測の限界（重要）

**成果（発生した報酬）はGA4に返ってきません。** 申込は広告主のサイトで完了するため、
GA4で分かるのは「クリックまで」です。したがって次のように使い分けます。

- **GA4** … どの配置・どのページがクリックを生んだか
- **ASPの管理画面** … 実際に発生した報酬

この2つを突き合わせて **1クリックあたりの報酬（EPC）** を出すと、
「クリックは多いが売れない配置」が見えます。クリック数だけで判断すると、
成約しない配置を強化してしまうので注意してください。

突き合わせを自動化したい場合は、ASPが提供する**サブID（パラメータ）**を
アフィリエイトリンクに付け、`position` の値を渡します。
ASPのレポート側で配置別の報酬が直接分かるようになります（対応可否はASPごとに異なります）。

## 6. 法令・規約まわり（未対応で公開すると危険）

- **ステマ規制（景表法）**：全ページ上部に「本ページはプロモーションを含みます」を常時表示しています。文言変更は可、削除は非推奨です。
- **アフィリエイトリンク**：`rel="sponsored nofollow noopener"` を自動付与しています（Googleの要件）。手書きでリンクを足す場合も必ず付けてください。
- **口コミ**：`reviews` はサンプル文です。**体験談の捏造は景表法違反**です。実際に集めた声に差し替えるまでは `reviews: []` にしてください。
- **「実質0円」表示**：`points` が月額以上だとシミュレーターが `¥0` と表示し、有利誤認になりかねません。`build.js` が検出して警告します。
- **数値の裏取り**：料金・作品数は変動します。公式サイトで確認し、更新日を `index.html` の「最終更新」に反映してください。

## 7. ローカルで確認する

```bash
# 開発中（ビルドなし・そのまま開いても動く）
cd affiliate && python3 -m http.server 8000

# 公開前の最終確認（実際に配信されるHTML）
node build.js && cd dist && python3 -m http.server 8000
```

## 8. 別ジャンルへの転用

`data/services.js` の項目（`price` / `trialDays` / `works` / `simultaneous` / `points` …）を
扱う商材に読み替え、`js/render.js` の `ROWS` と `serviceCard()` 内の
`<table class="spec">` の行を書き換えれば、そのまま別ジャンルの比較サイトになります。
