# フルトリランナー ── デザイン作業の引き継ぎ（Codex 向け）

坂を転がる果物を操作して、向かってくる動物を押し倒し、最後のクマを倒してゴールする
ブラウザゲーム（RTA）。**遊びの形はもう決まっている。ここからは「見た目」を詰めたい。**

このリポジトリを渡すので、**絵作りを担当してほしい。**

---

## 1. まず動かす

```bash
cd fruit-rta
python3 -m http.server 8000      # どんな静的サーバでもよい
# → http://localhost:8000/ を開く
```

配布用の 1 枚 HTML を作るとき：

```bash
node build.js                    # → dist/furutori-runner.html（スプライトを埋め込んだ単体ファイル）
```

ビルドは必須ではない。`index.html` を直接開いて作業してよい（`file://` ではスプライトが
読めないので、必ずサーバ越しに開くこと）。

---

## 2. 触ってほしいファイル

| ファイル | 中身 | 触る |
|---|---|---|
| **`theme.js`** | **色・線の太さ・スプライトの大きさ。見た目の値はぜんぶここ** | ◎ ここが主戦場 |
| **`assets/*.png`** | キャラクターのスプライト（透過 PNG） | ◎ 描き替え・追加 |
| `index.html` | HUD とカードの CSS（スコア・タイム・リザルト画面） | ○ |
| `game.js` | 進行・当たり判定・描画の手続き | △ 形を足すときだけ |
| `README.md` | ルールと数字の設計 | × |
| `design/` | **採用済みの絵柄資料**（最優先の基準） | × |

`game.js` に色やサイズを直書きしないこと。`theme.js` に足して、そこから読む。

---

## 3. 絵柄のルール（変更不可）

`design/CHARACTER-DESIGN.md` が正。要点だけ：

- 太く滑らかな**黒い輪郭線**（`THEME.ink` ひとつ）
- **ベタ塗り**。グラデーション・光沢・写実・落ち影は使わない
- 丸く単純化した、ひと目で読めるシルエット
- **動物は常に笑顔**。怖さは体格と笑顔との落差で出す
- 採用済みの配色・衣装（少年のキャップ、オーバーオール、木箱）は変えない

> **例外がひとつある。** 負けたときの「最期の演出」だけは、発注者の指示で
> 血しぶき・爪痕を出している（`design/` のルールでは血はゴア禁止）。
> ここは**意図的な逸脱なので、戻さないこと**。ただしタッチは他と揃える
> ＝ベタ塗り＋太い黒フチ。写実的な血にはしない。

## 4. 画面に出ているもの（＝デザイン対象）

括弧内は `game.js` の描画関数。手続きを変えたいときはそこを見る。

### 背景
- 空・雲（`drawSky`）／遠くの山（`drawSky` 内）／草地・道の縞（`drawRoad`）
- 道ばたの木（`drawTree`）、つまずく石（`drawRock`）

### プレイヤー
- **転がる果物の群れ**（`render` 内の `fruit` と `drawFruit`）。数が増えるほど横に広がり、
  一粒ずつ大きさ・跳ね・位置がずれる。`THEME.fruits` に色、`fruitSize` に大きさ
- 少年（`boy-back` / `boy-fall`）。出だしで走って、こけて、以後は坂の上に倒れたまま

### 仕掛け
- ゲート（`drawGate`）── 左右 2 枚。くぐった側の計算が適用される
- 壁のパネル（`drawLadder`）── 左右の壁に並ぶ `+N`。寄った側だけ拾える。黄＝大、青＝小
- 木箱（`drawCrate`）── 数字ぶんの果物を消費して壊す
- 大群の立て札（`drawWaveSigns`）

### 動物
- ウリ坊・サル・イノシシ・クマ（スプライト＋頭上の体力バー）
- ボスの強化クマ（`drawBoss`）── 頭上に大きな体力バー、足元に赤い危険域

### 最期の演出（`updateDeath` / `drawDeathOverlay` / `drawChaseBear`）
- 暗転 → 坂の上へカット → クマが駆け上がる → 咥えて振り回す → 赤黒く沈む

### HUD（`index.html` の CSS）
- Score / 果物の数 / タイム / BEST / 進捗バー / 操作ヒント / リザルトのカード

## 5. スプライトの決まり

- 透過 PNG、`assets/` に置く。ファイル名がそのまま識別子（`assets/bear.png` → `'bear'`）
- **足元が絵の下端**、**中心が絵の横中央**。ここを基準に地面へ立たせている
- 高さは `THEME` のワールド単位（`bossH: 7.6` など）と `ANIMALS[].h` で決まる。
  画像の縦横比は保たれるので、**横幅は気にせず縦で揃える**
- 新しい絵を足したら `game.js` の読み込みリストに名前を追加する：
  ```js
  ['boy-back', 'boy-fall', 'bear', 'monkey', 'boar', 'uribou', 'boss-bear'].forEach(...)
  ```
- 今ある 10 枚のうち、**使っているのは 7 枚**：
  `boy-back`（走り）`boy-fall`（転倒）`uribou` `monkey` `boar` `bear` `boss-bear`
- **未使用が 3 枚**：`boy-front` `boy-side` `boss-mafia`。
  `boss-mafia` は 2 体目のボスとして使える

## 6. 場面をすぐ出す（コンソール）

```js
FruitRTA.start()          // 出だし（こけるところ）からやり直す
FruitRTA.setCount(300)    // 果物の数を変える（群れの広がりを確かめる）
FruitRTA.jump(260)        // 好きな地点へ飛ぶ（壁パネル・木箱・大群）
FruitRTA.toBoss()         // ボスの手前へ
FruitRTA.die()            // 最期の演出を再生する
FruitRTA.pause(true)      // 止めて 1 枚絵として眺める
```

## 7. お願いしたいこと（優先順）

1. **動きの絵を増やす。** いまキャラクターは 1 枚絵の拡大縮小だけで動いている。
   - 少年の走り（2〜3 コマ）
   - 動物の歩き（各 2 コマ）── 大群が波打って見えるように
   - ボスの振りかぶり／叩きつけ（2 コマ）
   足すときは `assets/` に `bear-1.png` `bear-2.png` のように並べ、`THEME` に
   コマ割りの速さを置いて、`sprite()` の呼び出し側で切り替える形にしてほしい。
2. **ゲート・壁パネル・木箱の作り込み。** いまは canvas の矩形。木の板、看板、
   ネオンなど、世界観に合う造形にしたい（`drawGate` / `drawLadder` / `drawCrate`）。
3. **背景のバリエーション。** 夕方・夜・雪など。`theme.js` の色を差し替えるだけで
   切り替わる形（`THEME.scenes = { day: {...}, dusk: {...} }` のような構造）にできると嬉しい。
4. **HUD とリザルト画面。** 数字がただ置いてあるだけなので、ゲームらしく。
5. **最期の演出の詰め。** 咥えて振り回すところが 1 枚絵の揺れなので、コマがほしい。

## 8. 触らないでほしいところ

見た目の話ではなく、遊びのバランスを決めている数字。

- `MAX_FRUIT`（果物の上限 400）、`EXPECT[]`（想定カーブ）
- `ANIMALS` の `hp`（ウリ坊/サル=1、イノシシ=10、クマ=50）と `sp`
- `crowdSpan` / `crowdLen` / `crowdCX`（群れの広がり方＝当たり判定そのもの）
- 動物が群れへ寄ってくる係数（**端に残って素通り、が起きないようにしてある**）
- `makeGate` / `makeLadder` / `makeCrate` の値の作り方

大きさだけは `THEME` から変えられるようにしてあるが、**当たり幅に効く値
（`ANIMALS[].w`）を変えたら、通しで遊んで確かめてほしい。**

---

## 9. 確認の仕方

`node build.js` が通ること、コンソールにエラーが出ないこと、そして
**出だし → 壁パネル → 木箱 → 大群 → ボス → 最期** をひと通り目で見ること。
数字の見え方（果物の数・体力・タイム）が読めなくなっていないかも見てほしい。
